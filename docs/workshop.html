/writing · /writing/[slug]Writing

Index with tags, then long-form articles. Peer register. Paginated once it needs it.

/lab · /lab/[slug]Lab

Experiments. Each entry either embeds a demo, links out to a repo or hosted build, or is a short write-up. External builds can live on subpaths later.

/work/[slug]Case permalinks

Optional. The same story rendered on its own page, so you can send one link to a recruiter. Costs nothing: cases are their own stories anyway.

Why one page. A hiring manager gives a portfolio about two minutes. One scroll with an anchored index lets them skim the reframes, open the one case that matches their role, and reach the record without page loads.

03
Case anatomy

Built from blocks, not screenshots

Each block is a Storyblok component. Images are optional everywhere; the geometric language does the visual work, so a case with zero assets still looks finished.

reframeAsked / Actually

Two statements, the first struck through in red. The hook of every case.

contextSituation

Client, sector, my role, team, duration as a compact spec strip.

findingWhat I saw

Pull-quote scale observation. "He told them which boiler they'd get."

optionsOptions weighed

2 to 4 columns, one marked chosen, each with a why. Shows judgement.

diagramGeometric diagram

Steps, before/after, or system map drawn from data in CSS shapes. No assets.

metricNumber

Big figure with the caveat underneath, e.g. what it was measured against.

constraint_listConstraints

What boxed the work in. Pricing, production, deadlines.

reflectionHindsight

What happened next and what I'd change. Where Forgemasters gets its honest ending.

Design directions

Constructivism, with the volume down

All three use the same rules: one red, one black, one paper; type as image; geometry instead of photography; diagonals used sparingly as emphasis rather than everywhere. They differ in how loud the geometry gets.

C

Slab Index

Rodchenko's typography rather than his geometry: wide heavy type, black slabs with knocked-out text, vertical spine labels. Most confident, most poster-like. Leans on numbers, so it rewards the cases that have them.

Display + body: Archivo (wide + narrow)
Data: IBM Plex Mono

Storyblok: section tone (paper, ink, red) flips whole blocks; metric strips are their own block.

My pick: A, borrowing B's construction grid on the Record section. A gives the strongest identity with the fewest elements, and the struck-through "Asked" line is a device only your content has. Showing the faint grid on the CV timeline signals structure where the content is most structured.

06
Delivery

Publish, build, flat HTML

1Publish

Story published in Storyblok.

2Webhook

Storyblok calls the Cloudflare Pages deploy hook.

3Build

Pages pulls main, runs nuxt generate with the public token.

4Crawl

Every story pre-rendered from the Storyblok links API. No runtime API calls.

5Serve

Static files on the edge at martinalcock.co.uk.

Editing preview

The Visual Editor needs live drafts, which flat HTML can't give. A preview branch deploys the same app to a Pages preview URL built with the preview token and draft mode on. The editor points there. Production never sees drafts.

Code pushes

Pushes to main build production as normal. PRs get Pages preview URLs for free. Vercel and Netlify config gets removed.
